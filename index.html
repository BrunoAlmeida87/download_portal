Como o DocFlow confirma um download

Para cada documento da fila o sistema tenta a via verificada: baixa o arquivo por fetch, confere o código HTTP, o tipo de conteúdo e o tamanho em bytes, e só então entrega o arquivo ao navegador. Isso permite dizer com certeza que o documento chegou — e quanto pesou.

Quando o navegador bloqueia essa verificação (política CORS, página em HTTPS acessando API em HTTP, ou rede fora da intranet), o DocFlow não desiste: abre o documento em uma nova aba, como a ferramenta antiga fazia, e marca o item como “Aguardando conferência” — porque o navegador não permite que o JavaScript saiba se aquele download terminou.

O que cada status significa

Sucesso Arquivo baixado e conferido (bytes recebidos > 0). Aguardando Aba aberta pelo modo clássico. Confira a pasta de downloads. Falha Servidor recusou, tempo esgotado, resposta vazia ou pop-up bloqueado. Cancelado Interrompido manualmente antes de terminar.

Publicar no GitHub Pages

Funciona — o DocFlow é inteiramente client-side (um único HTML, sem servidor, sem dependências externas). Três pontos definem a experiência de quem acessar:

Hospedagem: nenhum documento passa por servidores externos. O download vai direto do portal da intranet para a máquina de quem clicou.
HTTPS × HTTP: o Pages serve apenas em HTTPS e a API do portal é HTTP. O navegador bloqueia esse cruzamento (mixed content), então a confirmação automática não estará disponível e o DocFlow operará em modo clássico. Continua baixando; deixa de confirmar sozinho.
Rede e visibilidade: quem abrir a página precisa estar na rede da empresa ou VPN. E, se o repositório for público, o endereço interno do portal fica visível no código-fonte — prefira repositório privado.

Para confirmação automática funcionando, use o arquivo local (abrindo direto do disco ou de um compartilhamento interno) ou peça à TI para publicar a API em HTTPS com CORS liberado.
