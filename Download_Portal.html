Gerenciador de Downloads — uso interno. Os downloads são feitos diretamente pelo seu navegador; nenhum documento passa por servidores externos.

Configurações

A "URL base" é o endereço para o qual o código do documento é anexado ao clicar em iniciar. O padrão aponta para o portal da intranet.

Como funciona

1. Cole a lista de códigos de documentos e clique em "Adicionar à fila".

2. Clique em Iniciar. Para cada item, o sistema tenta baixar o arquivo diretamente (via fetch) para confirmar se deu certo. Se o navegador bloquear essa verificação (CORS, ou a página estiver em HTTPS e a API em HTTP — "conteúdo misto"), ele volta automaticamente para o modo clássico: abre o link em uma nova aba, exatamente como a versão anterior desta ferramenta. Nesse caso o item fica marcado como "Não verificado", pois o navegador não deixa o JavaScript saber se o download realmente terminou.

3. Ao final, baixe o relatório em CSV com o status de cada documento, ou apenas a lista dos que falharam/não foram verificados para conferir manualmente ou tentar novamente.

Publicar no GitHub Pages? Sim, é possível — o arquivo é 100% client-side (HTML/CSS/JS), sem backend. Mas atenção:

  • O navegador de quem acessa a página precisa estar na rede da empresa (ou VPN) para alcançar api-doc.icnavais.net — hospedar no Pages não muda isso.
  • GitHub Pages só serve em HTTPS. Como a API é HTTP, a confirmação automática (fetch) será bloqueada pelo navegador ("mixed content") e o sistema usará sempre o modo clássico — ainda funciona para baixar, só não confirma automaticamente.
  • Se o repositório for público, qualquer pessoa pode ver o nome do host interno no código-fonte. Prefira um repositório privado.
